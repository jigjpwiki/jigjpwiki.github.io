# 管理者向けクイックガイド

1. ログイン後、カテゴリから対象を検索。セルはEnterで編集・確定、Escで取消。複雑な関連情報は「詳細」で編集する。
2. 変更は共有下書きに集まる。「保存済み」を確認してから閉じる。カテゴリ移動では下書きを破棄しない。Undo/Redoは下書きの操作で、GitHubの履歴を戻す操作ではない。
3. 複数行を選択したら件数と「選択対象を確認」を読む。フィルターを変えても選択は残る。「選択中の項目だけを表示」で全対象を確認し、不要なら「選択解除」。一括適用は下書きの変更のみ。
4. 「変更内容」で提出対象だけを選ぶ。関連する新規親子レコードを切り離さない。理由を入力してプレビューし、差分・参照影響を確認してからPRを作成する。上限は保存120操作/512KiB、保存期限30日。提出はAPI/preview制約にも従い、必要なら分割。未提出分は残る。
5. PR作成だけでは公開サイトやWikiには反映されない。GitHubのFiles changed・CIを確認し、人間がレビューしてマージする。Adminはmainへ直接書き込まない。

## 困った場合

- **保存失敗・429・503・ネットワーク切断**：元タブを閉じず入力を保持し、接続回復後に「下書きを保存」。保存成功前の再読み込みは避ける。
- **セッション期限**：元タブは保持し、案内から別タブで同じアカウントに再ログイン。元タブの「ログインを確認して保存を再試行」を押す。別管理者では再開できない。
- **別タブ/CAS競合**：入力を閉じず、別タブの保存を確認。競合している下書きを黙って上書きしない。必要な値を確認して再適用する。
- **main更新**：最新mainへ再適用し、3-way差分を確認。異なる値は人間が選び、再プレビューする。
- **PR応答不明**：同じ提出の再試行を使う。別の新規PRとして繰り返さない。「提出済みPR」でも確認する。
- **CI失敗**：PRの失敗ログと差分を確認。Schema/ID/参照エラーを直して再プレビューし、許可された同じPRの更新を使う。テストを無効化して通さない。
- **PRが手動変更/close/merge済み**：自動上書きできない。GitHubで状態を確認し、最新mainから必要な変更だけ再提案する。
- **下書き破棄/期限切れ**：保存期限を確認し、破棄は対象を確認して実施。期限切れの未提出内容の永久復旧は保証しない。

Workerの切戻しは[所有者向け手順](DEPLOY.md)で行う。DO削除・SESSION_KEY変更・master自動revertは行わない。
