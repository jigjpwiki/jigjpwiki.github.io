# vNext 5 設計（実装前）

## 問題と情報設計

Phase4 main 366cb245cから開始。activity/agency/visibilityを独立セルとして並べると、退所にdraftを併せて設定する誤操作が起き、全マスター検証で初めて停止する。公開参照検証は非公開レコードの内部履歴まで参照として数えていた。新規の保存基盤は作らず、目的別操作→変更案・影響→確認→既存Workspaceへ1回のreplace→最終サーバー検証とする。

- 人物一覧/詳細:「状態・掲載を変更」入口。複数行選択を再利用し10人に同じ目的を原子的に適用。
- 操作:開始/休止/再開/引退/終了/所属/退所/移籍/グループ加入/脱退/掲載開始/掲載停止。
- 直接編集は維持し、危険な非公開化には事前影響エラーと目的別操作への案内を出す。
- カテゴリ一覧は現行高密度テーブル、グッズは現行親子登録、変更内容/提出済みPRは既存共通画面を維持。目的別編集を全画面共通テーブルへ押し込まない。

## 状態遷移

活動状態だけの操作は所属/公開を変更しない。退所は選択したcurrent所属をformerにして終了日（不明ならnull）を保存、活動状態は維持。残るcurrent所属がなければ所属状態はunknown（未所属を推定しない）。移籍は旧履歴を保存して新currentを追加。所属状態affiliatedはcurrent所属がある場合のみ。グループ脱退は現行名簿からのみ除外し、過去イベント/商品/歌唱等には触れない。グループの旧名簿は後方互換のformerTalentIdsへ保持し、現名簿と分離。加入/脱退日は確認できても専用フィールドがないため架空プロパティへ保存しない。活動終了日専用フィールドも追加しない。

## 公開方針

visibility public/draftは維持。追加は任意boolean historyNamePublicのみ（draft時に限る）。既定false。

1. 名前を公開履歴に残す（明示確認）: draft + historyNamePublic=true。人物一覧/プロフィール/検索/配信照合から外す。関連イベント等は維持し、公開投影には固定IDと表示名とprofileHidden=trueのみ。画像/SNS/所属/状態等を公開投影しない。リンクは無効なプロフィールではなく名前のテキスト。名前は意図して公開されるので「完全非公開」と呼ばない。
2. 関連情報も非公開: draft、flagなし。直接参照の公開レコードと、それを参照する公開レコードの閉包をdraft化する案を全件表示。原本の履歴/価格/IDは保持し、他出演者を含むレコードも隠れることを明示して承認。自動匿名化・人物ID削除・商品統合は行わない。

生の公開feedはdraft人物の確認済みaccount ID（名前推定の照合なし）および明示的な非公開名の出現で除外する。収集元JSON/Worker/収集対象を変更しない。未識別の自由文・外部サイト・既に配信済みキャッシュの完全な回収は保証できず、完全非公開時は管理者の内容確認を必須とする。公開用の投影をbuildとAdmin確定検証で共通化し、個人に紐づく公開recordの検証を削除しない。

## 整合性と互換性

ローカルでは操作選択・計画生成・一括確定前に所属/参照/容量を検査。下書き保存は未完成を保持する既存仕様のため不正draftを消さず、プレビュー時に全masterを検証、main SHA・確認hash・権限・CSRF・監査・PR直前検証を維持。全体の計画生成に失敗すればWorkspace.replaceしない。1回のUndoで目的別の複数操作を戻せる。

新Schemaは既存v2レコードを受理。historyNamePublicを含むPR作成/データマージ前に互換Workerを所有者承認で導入する必要がある。旧Workerへ戻すと新フィールドを検証できないため、新flag導入後は対応Workerへrollbackする。deploy/vars/Secrets変更は本PRで行わない。

## デザイン根拠と検証

DADSのラベル/エラー/フォーカス、GitHubの変更案と確定の区別、Linearの目的別操作、Notionの一覧と詳細の切替を既存ローカルトークンに適用する。外部製品のコンポーネント/ロゴ/画像はコピーしない。現行と変更後の実ブラウザー操作数をA〜Eで比較、320〜1920/ライト・ダーク/キーボード、全root/Admin/Workerを検証する。実ATと本番運用は別に未検証として記録。

## 追加UI要件

通常一覧を既定にし、人物をマスターの事務所順・登録順で1回ずつ表示（複数所属は最初の現在事務所を代表、カードには全所属）。旧所属のみ/無所属/不明を分ける。97名は全件DOM、ページ番号なし。200件超は検索対象を全件に保ち「続きを表示」で連続追加。大量編集は明示した一括編集モードの50行テーブルへ分離。各カテゴリの通常一覧は内容に合わせた要約、複雑な商品/販売/セットリストは既存の階層詳細で編集。

tokens.cssを唯一のトークン定義とし旧app/workbenchのroot再定義を廃止。app.cssはフォーム・提出、workbench.cssはテーブル・パネル、design-system.cssは共通レイアウトと通常一覧を担当。Stack/Inline/ButtonGroup/PageSectionで折り返し時もgapを維持。主要な成功操作はGitHubでPRを開くへ統一。公開サイトCSSを変更しない。
