# 検証結果と比較

## 再現環境と検証範囲

Node 24 / Chromium 156、実ブラウザーとローカルWorker/SQLite。実サービスへのPR書込み・本番認証・Cloudflareデプロイは実施していない。GitHubはモック、現行全マスターと固定fixtureを分離して検証した。

- root: check、197単体テスト、build、全browser test。
- Admin: 94単体テスト、check（静的validator/build含む）、Worker/SQLite、全browser test。
- 既存OAuth/所有者分離/CSRF/暗号化/CAS/監査/hash/部分提出/3-way/二重送信復旧のテストを維持。通常一覧導入で旧テーブルのテストを削除せず、一括編集へ明示的に切り替えて検証。
- 正常なAdmin編集後にroot全検証するprospectiveテストに、履歴名を残す公開停止も追加。現マスターの可変状態・公開数を固定しない。意図的な重複・不正URL・無効参照は拒否。
- 活動終了10人の原子的変更、退所と活動の独立性、移籍の旧履歴、グループ脱退履歴、Undo、既存の未完成下書きの保全を検証。
- 公開停止は最小履歴投影/完全非表示の両方を、提出計画と実静的buildで確認。全97人が履歴名のみでもプロフィールページを生成しない。非公開のlocal画像の出力除去、共有公開画像の保全、配信IDの大小文字/プラットフォーム分離、自由文保留、関連Campaignの逆依存も検証。

## UI・視覚レビュー

320/390/768/1440/1920px × light/dark。ダッシュボード、全カテゴリ、詳細、目的別影響確認、一括編集、下書き、入力/参照/保存エラー、競合、空/読込中、PR preview/成功を実操作で確認。213のlayout検査、217画面記録。ドキュメント横はみ出し、操作群の重なり、4px未満の操作間隔を検出する。例外的に一括編集表内部の横スクロールは許可し、人物名/選択を固定。

スクリーンショットの視覚確認で、モバイルの検索条件による一覧押下げ、画像失敗時の長文、入れ子の余白、入力境界コントラスト、成功画面の主操作を修正した。最新の通常一覧は詳細条件を折りたたみ、初画面から人物を表示する。Before/Afterの同viewport画像は[README](README.md)参照。

キーボードはnative controls、スキップ、focus、Enter/Esc/Tab/矢印、一括選択・セル編集を確認。token単体テストでlight/darkの主要文字4.5:1、操作境界3:1以上を確認。全状態のWCAG適合認証、実VoiceOver/NVDA試験は未実施。

## 操作数・時間

数値は自動操作のクリック回数。文字入力・select変更・キー入力は別操作として加算しない。待機を含むテスト所要時間で、人間の習熟時間や本番応答速度を表さない。旧Phase4 frontendと新frontendを同じモックへ接続した比較。

| 作業 | Before | After | 意味 |
| --- | --- | --- | --- |
| 10人引退・保存・Undo | 16回 / 2.06秒 | 19回 / 1.93秒 | モード/目的/影響確認が増える。公開や所属を変更しない安全性を優先 |
| 公開停止 | 7回 / 1.10秒で参照エラー | 11回 / 1.36秒（履歴名）、1.63秒（関連非公開） | 事前方針選択から保存・復元・模擬PRまで完遂 |
| 移籍・模擬PR | 10回 / 1.12秒 | 11回 / 1.21秒 | 旧履歴と日付を確認した一括計画 |
| 20件変更（bulk A） | 26回 / 5.52秒 | 30回 / 4.35秒 | 通常一覧からbulkへ入る分を含む |
| 通信障害復旧（bulk D） | 26回 / 11.34秒 | 30回 / 4.50秒 | 保存429・PR成功応答紛失、意図的障害2種以外0例外 |
| 100件を60+40で部分提出（bulk E） | 178回 / 31.89秒 | 183回 / 15.99秒 | 同じfixtureで計測。全ケースが短縮したとは主張しない |

Campaign＋複数Product＋Offerの新規登録・既存Campaign追加・終了Offer編集も4幅の既存E2Eで確認済み。これらのクリック数の独立したBefore/After計測は未実施。

## 性能・一覧密度

97人は全件連続表示、ページ番号なし。1440pxでは3列、390pxでは1列で画像と名前を先に配置。1000人fixtureは初期200行を段階描画し全件検索（初期7.7ms、検索2.3ms）。ページングとは異なり連続追加でき、検索対象を描画済みに限定しない。

bulk同一fixture比較：1000人物/5000記念日/2000イベント/5000商品/10000歌唱/5000Offer。After初期12〜49.4ms、検索/絞り込み/ソート100.3ms以下、heap最大13.1MiB。閾値は初期1500ms・操作1000ms・heap128MiB。旧版も閾値内で、新版が常に高速という意味ではない。詳細はcurrent-bulk/quality-report.jsonとprevious-bulk/quality-report.json。

## 残る制約

未リンクの人物名/アカウントを含む公開自由文は自動判定せず手動確認が必要。非公開化の依存変更が120操作/512KiBを超えれば停止し、危険な自動分割はしない。共有履歴まで隠れる方針は確認画面で承認が必要。履歴名公開は完全な秘密化ではない。Git履歴/外部キャッシュの削除機能はない。

実本番の認証・設定維持・CPU/free quota・デプロイ/rollbackは所有者の承認後に確認する。デプロイ手順は[DEPLOY](DEPLOY.md)。DADSを参考に自前の軽量DOM/CSSで構築し、新依存・有料サービスは追加していない。
