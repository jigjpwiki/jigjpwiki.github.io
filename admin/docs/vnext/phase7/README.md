# Admin vNext 7

最新main 7b0d1b765 を起点とし、共通CMSの権限・画面・編集経路を統合する。仕様全文は REQUEST.md。

## 移行

既存ユーザーの scope と本人確認情報を保持する。contentPolicy がない場合は scoped-v1 として解釈する。新規招待は all-content-v1 を利用する。既存ユーザーの移行にはオーナーの confirmPolicyMigration による明示確認が必要。ロール変更・ポリシー変更は既存方式でセッションを失効させる。

本番適用前に最新の稼働バージョン・変数・Secret登録名・DO namespaceを取得し、既存 verify-production.cjs で照合する。新しいローカル設定の初期値を本番へ適用しない。切り戻し前は公開ジョブの状態を確認し、必要なら既存の公開停止フラグで処理を止める。SESSION_KEY とDOを維持する。

- 一覧に関連情報、日時、状態、公開状態、画像、検索、状態フィルター、表示列設定、50件ずつの描画を追加。共通ナビゲーションにローカルSVGアイコン、Ctrl/Command+Kの全体検索遷移を追加。
- 既存の有効な招待・登録済みユーザーを一括移行するオーナー専用APIと確認UIを追加。ロール・ID・本人確認・期限・旧scopeを保存し、移行時は既存セッションを失効。無効ユーザー、期限切れ未承認招待、移行対象の公開処理中ジョブは保護。通常の新規招待はロールのみ選択する。

### 編集フォーム改善と旧回帰テスト修正
- 旧Phase 3の保存ヘルパーが別画面へ遷移してUndo検証を破壊していたため、同一ルートの保存に戻し、画面遷移がないことも検証。
- 共通CMSの一覧と編集フォームをデスクトップで並列表示し、狭い画面ではフォームを上に表示。必須項目、近接エラー、画像プレビュー、保存中・保存済み・失敗の表示、関連レコードへの深いリンクを追加。保存中は移動を止め、非同期詳細取得の競合を防止。
- 共通権限での掲載状態と既存レコードの関連人物・グループ・事務所編集を既存の検証済み下書き・公開経路に追加。オーナーAPIをGoogleへ開放していない。販売枠の既存商品・キャンペーン紐付けは従来の公開制約に合わせ固定。
- 未完了：高度管理の全操作の移植、実際の画面レビュー、ブラウザーCI全成功。本番変更なし。
- ダッシュボードに実データに基づく下書き件数・要確認件数・コレクション件数を追加。公開処理の段階とコミット参照、差分の2列表示、選択変更時の公開確認の無効化を追加。公開ジョブや下書きの実データは推測しない。
- 新共通CMSのブラウザー検証を旧回帰テストと独立して実行し、スクリーンショットをActions成果物として7日間保持する構成。旧テスト失敗時も新画面の検証結果を取得できる。外部ステージングや本番への接続は行わない。
- 全範囲の編集者に一括編集を追加。最大12件の掲載状態、VTuber活動状態、歌唱確認状態を単一の検証済みプランで下書きへ登録する。CASにより一括保存し、既存下書きと重複する対象は全体を拒否する。任意フィールド・固定ID・アカウントを一括変更しない。公開は通常の差分確認とCIを経由する。
- 関連レコード選択を共通の検索付きセレクトに統一し、候補は50件まで＋選択済みを保持。出演者・所属メンバー・歌唱者は選択済み保持型の複数選択UIを再利用。モバイルではメニューボタンでナビゲーションを折りたたみ、Google編集者は初期状態で閉じる。旧オーナーの操作互換性を保持するためオーナー側は初期展開。フォームのaria-labelを明示し、前回CIの掲載状態ラベル取得失敗を修正。画面キャプチャは初期画面・編集直後にも取得する。
