# jigdule 3.0 第2段階

PR #8は2026-11-15 JSTにマージ済み（merge fdd57d64）。最新main 6d0df9746を確認して開始。A=共通データ/記念日、B=A依存のタレント詳細、C=B依存のグッズUIの積み重ねPRとする。マージ・本番設定変更・Wiki書込みは行わない。

## 共通データ

- talents.jsonと固定内部IDは第1段階の正本を維持。所属・活動状態を日付や配信頻度から推定・変更しない。
- catalog.json: 共通出典（talents.json既存出典とIDを重複させない）と人物以外のgroup-ID。organization-IDは事務所、group-IDはユニット等で別参照。グループのtalentIdsは登録済みの関連人物だけ。membersComplete=falseなら完全な名簿とは主張しない。
- anniversaries.json: ann-ID、分類、表示名、talentIds/groupIds、月日と任意の起点年、年次繰返し、周年表示可否、sourceRefs、public/draft。
- goods.json: product-ID（商品）、campaign-ID（企画）、offer-ID（販売機会）を分離。再販ではproduct-IDは同一商品として保持し、offer-IDは新規発行する。別商品へ既存商品IDを転用しない。価格と販売期間、購入URL、確認時点の手動状態はofferに記録する。未知の価格/通貨/時刻はnull。
- catalog-id-registry.jsonは発行済みIDの予約台帳。追記とし再利用しない。管理用で非公開。

SchemaはadditionalProperties:false、URLはHTTPS/認証埋込・秘密query拒否。ID一意性、出典・人物・組織・グループ・商品・企画の存在、publicからdraftへの参照禁止、日付/金額/期間/周年の整合性を意味的検証する。自動検証は出典内容の真実性や、意図的に台帳とデータを同時書換えする操作までは保証しない。人物同定、状態変更、IDの発行・統合は人間のレビューを必須とする。

原本は分離し、表示名や所属を各機能へ手入力しない。公開時に生成した投影・HTMLには必要な参照情報を含める。draftはHTML/公開JSONから除外し、公開情報が使う出典だけを渡す。Schemas/ID台帳/原レスポンス/認証情報はallowlistへ追加しない。

## A: 記念日

日本時間の当日と当月を使い、月移動・今月へ戻る・種類/所属（過去所属も含む）の絞込みを提供。直近一覧は当日から29日後までの30日間。年末は翌年まで列挙し同日に複数件を表示する。

2月29日は閏年の2月29日だけに表示し、平年の2/28や3/1へ移さない。誕生日では生年不明をnullとし、周年/年齢を表示しない。デビュー等の起点年が確認できた場合だけ周年を表示し、初年度の0周年は出さない。未来の起点より前の年へ遡って生成しない。単発記念日は年を必須とする。

初期8件: 誕生日4件（真昼ねる1/18、火乃晴るい8/3、水透ユウ4/11、李じゅぴ汰11/29）、個人デビュー3件（火乃晴るい・水透ユウ・李じゅぴ汰:2025/3/7）、ProForma Nova STAR 1期生グループ記念日1件（同日）。

誕生日は第1段階で実取得した公式プロフィール・Wikiの項目を照合した。3/7の起点は今回[公式発表](https://www.proforma-production.jp/news/n/q1rm0p3exwy3)を実取得し、日付と4名の紹介を確認した。マスター未登録の銘兎目あうは名前から仮IDを作らず、グループの関連タレントを登録済み3名に限定しmembersComplete=falseとした。

真昼ねるのWikiの初配信日は2021/9/4、加入日は2024/12/28。[2025/1/8の公式Moon発表](https://www.proforma-production.jp/news/n/0m7ea1jigs1w)にも既にVTuberとして活動していたとの説明がある。これを個人の初デビューと混同しない。2021年の起点は今回公式一次情報まで確認できていないため、個人デビュー記念日は未登録。生年は全員未登録。

HTMLはビルド時生成し、JS無効時もビルド時点の月と30日一覧を表示する。JS有効時は表示時のJSTで再描画し、復帰・日付跨ぎも補正。月移動/絞込みのみJSが必要で、失敗時は静的HTMLを残す。小画面の月間表はフォーカス可能な横スクロール領域。詳細未実装のA時点では人物リンクは既存一覧のアンカーを使い、Bから詳細URLへ切り替える。

## ビルド・運用

追加サービス・DB・常駐サーバーなし。取得job、cron、Pagesのpermissions/concurrencyは変更しない。外部照合は手動登録時だけでbuild/ブラウザーにスクレイピングを組込まない。静的生成と軽量JS/CSS/JSONの追加だけで、画像の新たな複製や定期API呼出しを増やさない。カレンダーのSSRはJST日付が変わると内容が変わるため、通常実行時に日次で再公開判定へ反映する（同日内は安定）。

公開sitemapに実装済みルートだけを追加する。今後の商品/出典登録はvalidate→test→build→browserを通し、確認できない値を補完しない。登録範囲の拡充・確認周期・画像利用条件・複雑な販売バリエーションは継続課題。

## B: タレント詳細（Aに依存）

4名の`/talents/{id}/`を正本から静的生成し、一覧と記念日からリンクする。名前・肖像（失敗時はイニシャル/未確認）・現在/旧所属・公式アカウント・Wikiを中心に表示。内部ID、agency/activity管理コード、細かい履歴期間を主要表示にしない。卒業から引退を表示しない。出典は折りたたみ、各確認日と掲載出典の最終確認日を保持する。

YouTubeは厳密なchannel IDでyoutubeidを照合。Twitchは確認済みログインIDを大文字小文字正規化してtwitchidと照合し、表示名一致では関連付けない。YouTubeの動画IDとwatch URL、Twitchの動画ID/配信先アカウントとURLも検証して外部誤リンクを防ぐ。Twitchの数値user IDは現行データにないため、ログイン名変更時は人間がマスターを再確認する。

配信/動画は既存JSONのビルド時スナップショットで最大12件。人物の活動状態は変更せず、配信の状態も「収集時点」と明示する。オプションデータが欠損・非配列・不正なら関連欄は空状態とし、プロフィールは成立する。トップのクライアント更新や取得APIは変更しない。関連グッズのレンダラー接続はCで追加する。

## C: グッズ情報（Bに依存）

`/goods/`を生成し、商品画像/代替表示、商品名、人物/グループ、企画、価格、JST販売期間、販売先、状態、出典/確認日を表示する。詳細ページではIDで関連付くデータがある場合だけ関連グッズ欄を追加する。静的HTMLを基本とし、JSは判明した期間の表示更新と画像の漸進表示だけを担当する。

販売機会offerは商品productや企画campaignと別の固有ID。再販に新offer-IDを発行し、元の商品IDを別商品へ流用しない。未知の価格・日時はnullを保持。日だけ分かる期間はperiodNoteで原情報を保持し、23:59等の終了時刻を推定しない。購入URLは、当該URL自体を確認したofficial出典と一致させる。

状態はscheduled/on_sale/ended/sold_out/unknown。人間が確認したsold_out/endedを原データとして保持し、既知の開始前は販売予定、終了日時経過は販売終了と表示する。既知の終了時刻後は過去の売切れ状態より販売終了表示を優先する。期間内だから販売中とは推定せず、未知の状態は不明のまま。**日時からsold_outを生成しない。** JS無効時はビルド時点の状態と確認日時を表示し、最新は販売先を確認する。商品画像の取得失敗時もタイトルと価格・期間を読める代替表示を残す。

### 初期商品を公開しなかった理由

本人チャンネル説明から参照される[公式BOOTHの商品ページ](https://proforma-nova.booth.pm/items/7770929)を読み取り確認した。商品説明・複数バリエーションの価格・「2026年1月31日まで」という文言がある一方で、応答HTMLに「現在この商品は非公開中です」という表示も含まれていた。これが表示用テンプレートなのか現在の公開状態なのか、この確認だけでは確定できない。そのため当該情報を公開可能な新商品データとして登録しない。生の応答・未確認の価格/期間・ログインUI等は成果物へコピーしていない。

**公開登録は商品0件・企画0件・販売機会0件。** 空状態には、未登録が「販売中の商品が存在しない」ことを意味しないと明示する。機能は検証専用fixtureで、販売中/予定/終了/売り切れ/不明、複数販売期間、未知の日時/価格、画像欠損、関連人物/グループ、危険URL・HTML、draft除外をテストしている。fixtureはテストサーバーにのみ存在し、公開buildには含めない。

### 検証と継続課題

A/B/Cとも既存の配信回帰を維持し、カレンダー/詳細/グッズを1440/390/320pxで確認する。詳細は4件、記念日8件、グループ1件（関連人物は登録済みの一部）で、人物の正本・状態は変更しない。公開ファイルは検証済みデータの投影と生成HTMLのみ。内部台帳・Schema・調査物・fixture・Secretsを除外し、sitemapに実装済みルートだけを追加する。

継続課題は、確認済み商品の手動登録、複数価格バリエーションの正式な商品粒度、情報の再確認周期・訂正窓口、Twitch数値IDの導入、追加タレントとグループの網羅、日付精度/売切れ確認の運用。自動スクレイピング、在庫監視、Wiki書戻し、DB/APIサーバー導入は今回の範囲外。

レビュー順はPR #9（A）→ PR #10（B）→ C。各依存PRがマージされた後にbaseをmainへ付け替え、必要ならrebaseする。これらのマージやbase切替を自動実行せず、レビュー時に依存が残ることを明示する。

最終ローカル検証は全76 Nodeテスト、既存配信画面5幅、基盤3幅×JS有効/無効、新機能3幅＋JS無効の静的表示、check/build/actionlint、隔離した`npm ci --omit=dev`環境での実buildが成功。販売fixtureはローカルテストHTTPサーバーだけに存在し、成果物にテスト用ルートはない。計測時の公開物は197ファイル・約36.97MBで、大きな画像アセットの複製は追加していない。
