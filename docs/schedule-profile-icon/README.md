# スケジュールのプロフィール導線修正

PR #29のmainマージを確認し、最新main `3331e1500` から開始した独立PR。今回の範囲はアイコンの導線だけ。タレント一覧/詳細の再設計（PR B）と他の公開ページの統一（PR C）は、このPRが人間によりmainへマージされた後の最新mainから行う。

## 変更

- カード下の青いプロフィール文言とその余白用CSSを撤去。
- `.live-block` をレイアウト用のdivにし、配信先のネイティブaをオーバーレイとして配置。名前/タイトルによるアクセシブル名と、従来の別タブ表示を維持。
- 既存の検証済みアカウントID照合で人物を特定できたときだけ、アイコンをプロフィール用のaに置換する。配信先aの子孫にはしない。
- 装飾部分のポインター操作を配信先へ通し、アイコンは独立して操作可能にする。既存ホバーでカードが動いた場合もアイコンが覆われないことを実ブラウザーのhit-testで検証。
- 画像欠損/取得失敗時は同じ大きさの頭文字を残す。PC68px、モバイル48pxでリンクのタップ領域を確保。フォーカス/ホバーの輪郭を追加。
- 再描画後のフォーカス復元対象を配信先とプロフィールの両方に対応。
- 公開バージョンは既存規則に従い2.10.1。未実装の公開サイト再設計は告知しない。

ID照合・取得頻度・API・データ検証・Swiper設定・動画切替・公開allowlist・Worker・Admin認証・Secretsには変更なし。新しい依存やサービスも追加しない。

## 検証

- `npm run check` / `npm test`（174件）/ `npm run build` / `CHROMIUM_PATH=/usr/bin/chromium npm run test:browser` 成功。
- 320/390/768/1440pxでHTMLのa入れ子なし、旧テキストリンクなし、ID不一致にはプロフィール導線なし、画像取得失敗でも48px以上の操作領域を確認。
- カードの画像領域で配信先のリンクがhitし、アイコンではプロフィールリンクがhitする。Enterによる配信先の別タブ表示、Tabで2リンクを独立操作、Enterによるプロフィール遷移を検証。
- 320/390pxのtouch有効コンテキストで、アイコン上からの実touchドラッグによるSwiper移動と誤遷移なし、その後のアイコンタップ遷移を検証。
- 既存テストのタイトル/配信状態の参照先を、変更したDOM構造へ対応。検証内容は維持。
- スケジュールの16:9サムネイル、同一人物の別カードを含む再描画後のフォーカス復元、動画切替・日付切替・再取得/障害時保持・関連ページ・公開ファイル検証の既存ブラウザーテストも成功。
