# Official event/goods discovery and reviewed registration

This PR adds 3 events (total 5), 41 distinct products, 6 campaigns and 41 offers, from six official Palette Project goods announcements and three event announcements. `verified-goods.json` lists each factual price/name and announcement URL. Existing events, talent IDs, feeds and collectors are unchanged. Full-set bonuses without independent prices are not separate products. Single/BOX cans are separate products; named multi-member variations remain a single range at the same stated price. No artwork or article prose is redistributed.

Sources: https://paletteproject.jp/category/news/goods/ and https://paletteproject.jp/category/live-event/ . All six articles in the goods category were inspected; the official store links in those articles establish store ownership. BOOTH returned 403 and was not bypassed. X/TikTok are manual-only. The official footer prohibits unauthorized copying; robots allowing a path alone does **not** authorize collection. `sources.json` therefore starts at `needs_review`: default CLI makes zero external requests. A maintainer must review syndication/terms permission before setting `allowed`. A source can only fetch its enumerated path on enumerated hosts. No link recursion. RSS adapters extract minimal title/link/publication metadata, not article content. Source subject IDs and policy evidence are managed in the private registry.

`node scripts/discover-official.js` is manual, independent of existing scheduled collectors. Runtime checkpoint is atomic and gitignored, outside the publication allowlist. Maximum 4 requests / 60 seconds / 512KiB per response / 15-second request timeout / 2 redirects, daily source TTL, and Retry-After deferral. Each DNS result is checked; connection lookup is pinned to a checked public address. Rate limits stop the run; individual failures preserve existing candidates. Changed hashes invalidate confirmation into needs_review, keeping history. No new Actions schedule is enabled and no paid API is introduced.

Registration: `node scripts/plan-catalog-registration.js REVIEW.json OUTPUT.json` only produces a plan. Review includes baseHash of all six master files, confirmed patches with expectedHash, evidenceHash of the exact record, official sourceUrl and checkedAt. Existing IDs cannot change. Reuse product IDs for new offers; do not assign a product per resale. Plan validates schemas/references, provides full rollback and before/after changes. Re-run accepts the reviewed resultHash as well as the original baseHash; repeating the same confirmed records produces zero changes. Apply reviewed result files only in a PR. No apply command, eval or shell payload is supported.

Sale periods and prices are from official announcements (JPY, tax included); current availability is unknown because stock has not been checked. The renderer may indicate a future/elapsed stated sale window; elapsed never means sold out. End date for Canvas is null. Limited signed sets have their separately announced 24-hour windows; no invented availability. Birthday live announcements stay `scheduled`, not assumed actually held. The Hanon official report establishes a past event date; no midnight or inferred end is supplied. The Kotoha article has a contradictory **voice** sales deadline: that voice offer is deliberately not registered. Large concert's updated pre-sale period ends Nov 8 as stated by the corrected announcement; prior revision has not been observed, so no fabricated history.

Product detail pages `/goods/product-xxxxxx/` link list → product → official offer and talent profiles. C alone raises release 2.8.0 → 2.9.0 for this visitor feature; no later feature is announced. Sources, review ledgers and schemas remain unpublished. Further source adapters, authorized daily Actions automation, exact store variant IDs/stock and resale observations are follow-up work, not claimed complete.
