# External music identity assistance

MusicBrainz is a **community reference**, never official original evidence. Work, Recording, Release Group and Artist IDs are typed and kept separate; artist/release-group IDs are not unique Song identity. Core metadata is CC0; supplementary data has separate CC BY-SA licensing. See https://musicbrainz.org/doc/MusicBrainz_Database/License and https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting . Noncommercial free API, no API key, descriptive User-Agent `jigdule/2.8.0 (https://github.com/jigjpwiki/jigjpwiki.github.io)`, single process <=1 request/1.1 seconds, 7-day result cache, 6 requests/run, 60-second discovery budget, 15-second timeout, 512KiB response limit and 5 search results. Run one process per shared IP; external parallel consumers must share the limiter. 429/503 and Retry-After defer the checkpoint; there is no busy retry or key rotation. No new scheduled jobs/API quotas for existing YouTube collectors.

`node scripts/search-external-music.js ANALYSIS.json OUTPUT.json` consumes B `rows` (or a row array). Only song_candidate rows are queried. Confirmed existing ID **and exact official canonical/alias evidence** skip external calls; name-only suggestions do not. `createClient.get(type, query)` searches recording/work/release-group/artist; a UUID query performs a bounded entity lookup with typed work/artist/URL/release relationships. Parenthetical version qualifiers are preserved in search input. Suggestions, scores, disambiguation, artist credits, typed relations and internal matchSong suggestions remain pending. No full artist biographies, audio, artwork, lyrics or comments are stored. The private gitignored runtime is the cache/checkpoint, atomically written even after failure. Output is an explicitly named **private review file**, never a public master. Re-run the same input uses cached results without repeat API requests; an interrupted search can replay from cache.

Optional Song.externalIds requires provider/entity/id/exact entity URL/verified status/checkedAt. Duplicate Work or Recording across Song IDs fails validation; artist/release-group can be shared. `matchSong` surfaces verified external agreement as a reason but cannot approve. `resolveSong` refuses cross-canonical external matches until an official alias is independently reviewed, blocks new external refs on an existing record without an explicit expected-hash patch, and validates all masters. MusicBrainz/Wikidata URLs are rejected as identityUrl or canonical aliases even if incorrectly labelled official in an imported source. Existing Song registration still requires official work-level identityEvidence, separate from a performance's archive/comment evidence.
