# Adminで変更できる状態とテストの分離

PR #36の状態更新後、run 43948399318でroot単体185件中5件が失敗した。
`catalog`/`goods`/`talents`は李じゅぴ汰の状態がunknownであることを固定し、
`talent-details`は活動終了表示を無条件に禁止、`talents-b`は無所属状態を残したまま
所属不明表示を期待していた。データの正誤ではなく、実マスターとテストシナリオの混同が原因。

- 実マスター: 現行Schema v2・意味的整合性・ID台帳を検証し、投影・描画前後の完全一致を確認する。
- 固定シナリオ: 既存の`tests/fixtures/foundation-talents.json`を使用し、所属と活動の独立性・旧所属からの引退推測禁止を検証する。
- 状態マトリクス: unknown/unaffiliated/affiliated × unknown/active/hiatus/retired/endedの15通り。
  現所属と所属状態の矛盾、不正な状態コードは引き続き拒否する。
- Admin: Schema v2で出典なしの10通りの状態編集をプレビューし、他人物・元snapshot・固定ID台帳が変わらないことを検証する。
  各ケースの初期状態も固定し、実マスターと同じ状態だったためno_changesになる依存を避ける。
- ブラウザー: 実プロフィールは記録された状態に対応する表示を確認する。
  「旧所属だけでは活動終了と表示しない」は専用の固定fixtureルートで検証する。

`tests/fixtures/expansion-states.json`はPR #36マージの第一親
`3b10620d65ef7df68c18d03fd9df70a03db2e6cc`から抽出した97人の所属・活動状態の履歴。
過去の97人/旧所属13人/明記された活動終了6人の履歴検証を維持し、現在の状態には適用しない。
実マスターに履歴IDが存在することと、現在のマスター全体が検証に通ることは別々に確認する。
このfixtureは現状を正当化する台帳ではなく、当時のテストケースであり公開対象外。

人物情報の正しさの判断・活動終了の自動推定は行っていない。
マスター、Schema、公開UI、収集処理、Admin本体、バージョン番号は変更しない。
テストのみの修正のためリリース番号の更新は不要。
