# 公開UX再設計 PR A：配信とタレントの連携

## 現状調査と今回の範囲

main `9999452d9` から開始。`scripts/build-site.js` の公開allowlist、`lib/talent-details.js` のビルド時フィード埋め込み、`lib/related.js` のアカウント照合、`lib/site-pages.js` / `lib/info-pages.js` の共通ナビゲーション、`assets/js/talent-directory.js` の複合検索を確認した。

メインの `assets/js/app.js` はYouTube/Twitch/TikTokの公開JSONを取得し、Swiper・日別カード・動画トグルを描画している。加えて既存 `youtube-status.js` がブラウザーの共有キャッシュ・バックオフ付きでYouTube状態を補正している。タレント詳細はビルド時のYouTube/Twitchを保存データとして表示し、閲覧時には更新していなかった。

記念日は安定した静的フォールバック＋閲覧時JSTの暦、イベント/音楽/歌枠/グッズは個別マスターから静的生成する既存構成。今回これらの検索・一覧・情報設計は変更しない。事務所別一覧と詳細の本格再設計（PR B）、その他ページの統一（PR C）は、このPRが人間によりmainへマージされた後、最新mainから着手する。

## 参照サイトとデザイントークン

2026-11-16に https://www.jigdule.jp/ と https://www.jig.jp/ のHTMLをHTTP200で取得。jig.jpの公開CSSも200で確認した。白・淡いグレーの背景、黒系の本文、青いアクセント、日本語/欧文のフォント区分がある。Wikiの通常ページは403で、それ以上の取得や制限回避は実施していない。ヘッドレスブラウザーでの外部ページの直接撮影は接続が成立せず未確認。ローカル生成サイトを実際に撮影して目視確認した。

公式CSS・ロゴ・画像をコピーせず、既存jigduleの語彙を基準にする。

配信カード本体・Swiper・日付切替・動画トグル・更新処理のデザイン/動作を維持し、カードの外側に小さなプロフィールリンクを追加した。非公式サービスのロゴ・表記をそのまま維持。

## 照合と公開範囲

- `stream-core.js` をNodeの静的フォールバックとブラウザーで共有。表示名一致では照合しない。
- schema/出典検証と非公開除外を通したタレントから、`stream-talents.json` を作る。固定ID・名前・YouTubeチャンネルID/Twitchログイン名だけの縮小インデックスで、台帳・出典・非公開人物は含めない。
- Twitchは大小文字を正規化。ID欠損、不正ID、未登録、複数人物に紐づく曖昧なアカウントはリンクしない。
- 詳細の配信カードはURLのホスト・動画ID・Twitchパスも照合し、重複URLを除く。タイトルはtextContent/HTMLエスケープ。危険な画像URLは表示しない。
- 全人物の照合情報を各詳細HTMLへ重複埋め込みせず、共有インデックスを取得する。インデックス失敗時は人物を推測せず、検証済みの静的フォールバックを開く。

## 更新頻度・鮮度・失敗の扱い

| データ | 扱い |
| --- | --- |
| プロフィール・所属・記念日等 | GitHub masterを正本にビルド時生成 |
| 配信 | トップと同じ `/data/youtube.json`・`/data/twitch.json`、閲覧時/手動更新時にno-cacheで並列取得 |
| 収集日時 | `/data/last_updated.json` を並列取得。公開された収集日時であり、ブラウザー取得成功時刻で置き換えない |
| フィードの状態 | live/upcoming/archiveをそのまま使用。予定開始時刻を過ぎても配信中と推測しない |
| 古い/不明 | 収集日時から1時間超は注意、欠損/不正/未来日時は更新日時不明。配信予定日・出典確認日を鮮度に代用しない |
| 取得失敗 | プラットフォームごとに明示。再取得失敗時は直前の成功データとその日時を維持。初回全失敗時は保存データを開く |
| 空データ | 正常な空配列、紐づく配信なし、アカウント未登録を区別。過去に活動がないこととは解釈しない |
| JS無効 | 既存の保存データ・出典・アーカイブリンクを開いた状態で維持 |

1時間はUX上の注意しきい値で、SLA/障害判定ではない。メタデータのみの更新がフルデプロイを起こさない既存のfingerprint・未公開snapshot再試行機構は変更していないため、公開収集日時が古くても収集停止とは断定しない。

詳細ではYouTube API/状態補正APIを一切呼ばない。既存トップのYouTube状態補正・取得頻度・キャッシュは変更しないので、その補正が働いた場合は同じ公開フィードの表示から差が生じる場合がある。詳細には収集時点の情報と明記する。追加API消費0、定期取得ジョブ追加0。閲覧1回で静的JSON4件、手動更新でも同じ4件だけを取得する。定期ポーリングは追加しない。

配信中・配信予定・最近の配信の各最大6件を表示する。多くの予約がアーカイブを押し出さないよう別枠で制限し、詳細から配信先へ移動できる。スケジュール側は既存カードを残し、ID照合できる場合のみ別リンクを追加する。
