## 一覧の並び順と検索

`talent-directory.js` の純粋関数を静的生成/ブラウザーの両方で利用する。

1. 事務所はmasterのorganizations配列順。事務所内はtalents配列順。
2. 複数の現在所属がある場合は、organizations配列で最初の事務所を代表セクションにする。他の現所属もカードに表示する。絞り込み後も代表セクションは変えない。
3. 現所属がなければ、確認された無所属→旧所属のみ→所属不明の順に独立区分へ置く。旧所属を現所属へ読み替えない。各人物は一度だけ表示する。
4. 登録順は公開masterのtalents配列順。IDの数値順・デビュー順・年齢順ではない。静的HTMLを事務所別に並べても元の順序を保持するメタデータを使う。
5. 名前順は `Intl.Collator('ja', {numeric:true,sensitivity:'base'})`。同順位はmaster順で安定化。読み仮名の推測は行わない。

名前/別名はNFKC・大小文字・かな/カナを正規化して検索。事務所・現/旧所属・無所属・不明・グループ・並び順を併用できる。件数は人物単位で、複数所属でも二重計上しない。空のセクションは非表示。

URLの `q / organization / relation / group / sort` を読み書きする。標準順はsort省略。入力中の連続検索は1つの履歴にまとめ、選択条件変更と戻る/進むを区別する。IME変換中の中間文字は反映せず、確定後に反映する。URLの再読込/共有、プロフィールからのブラウザー「戻る」でも条件を復元する。未知の選択値は既定値に戻す。新しいHTMLと対応するCSS/JSには公開バージョンのクエリを付け、古いキャッシュとDOMの組み合わせを避ける。旧形式HTMLの場合は静的表示を保つ。URL値をHTMLとして解釈しない。

JS無効時も同じ代表基準の事務所別一覧を生成する。非公開人物と非公開グループはレンダラーでも除外し、公開前の既存master検証と参照検証も維持する。

## 人物の見せ方

- 一覧は円形画像・名前・現在/旧所属を中心にする。カード全体をリンクにし、繰り返しの「プロフィールを見る →」を廃止。
- 活動休止/引退/活動終了は、masterに明示された場合だけ補助表示する。卒業や配信頻度から判断しない。
- PCは小さな複数列、390pxは2列、320pxは画像と名前を横に置く1列。1人だけのセクションでも巨大カードにならない。
- 個別ページは最大128pxの画像と人物名・所属・公式リンクを先頭に集約。欠損/画像失敗時は頭文字を表示し、低解像度画像を巨大化しない。
- 配信中→予定→アーカイブ→記念日→存在する音楽/歌枠/イベント/グッズ→詳細プロフィール/活動履歴→情報源の順。登録のない関連カテゴリや空の音楽種別は省く。
- 誕生日の生年/年齢は推測しない。所属履歴・活動状態・出典は折りたたみへ置き、既存の出典URL・確認日時を保持する。別名・活動状態の出典も参照対象に含める。

## 配信カードと鮮度

- `.stream-media` を16:9に固定し、imgはabsolute/inset/width/heightで埋める。HTMLのwidth/height属性や原画像の縦横比に影響されず `object-fit:cover` で中央を切り取る。画像なし/失敗時も同じ枠。
- ON AIRは既存スケジュールと同じ赤い表示。YouTube赤/Twitch紫の線と短いプラットフォーム名、タイトル、JST日時、タレントの小さな画像を表示する。
- 状態は収集フィードのlive/upcoming/archiveを使用し、時刻経過だけでON AIRにしない。共通ID照合・URL検証・最大件数はPR Aのまま。
- 正常な空状態は「配信予定はありません。」「アーカイブはありません。」。配信先情報未登録は別表示にする。
- いずれかのフィードが失敗した場合は、そのプラットフォームを示して「取得できませんでした。」と表示。成功側は更新し、失敗側の前回成功データを維持。保存表示も開いた状態を維持し、不完全取得を「配信なし」とは表示しない。
- 詳しい更新時刻はセクションの「更新情報」に集約。古い/不明な更新日時は短い注意を通常表示にも出す。タイムスタンプをブラウザーの取得成功時刻で上書きしない。
- JS無効時はサイト公開時点の保存リンク・日時・情報源を開いた状態で閲覧できる。

YouTube API利用追加0、静的JSONは従来と同じ4件/詳細の閲覧または手動更新。追加ポーリング・DB・依存パッケージ・有料サービスなし。スケジュール用のapp.js・style.css・アイコン導線・Swiper・動画切替は変更しない。
